Architecture

What

A playground to experiment with MLP and NNs

Aim

Predict students degree delay (in months) given a set of features

Which stack

  • PyTorch and NumPy (of course)
  • PostgreSQL (and PgVector for embeddings)
  • Sqitch (because I need some Perl in any case!)
  • Emacs and ElPy as IDE (glad you asked!)

Approach

  • Phase 1: import data via ETL-like approach, prepare features
  • Phase 2: PyTorch stuff, two models defined
  • Phase 3: PgVector embeddings (just to try it, no useful features)

Part of the application has been developed with an agent support.

Phase 1: database

  • define database structure (using sqitch)
  • schema src mirrors original data (e.g., riga_libretto) in an anonymous (quasi) way
  • schema public contains student, enrollment, course, department and join tables
  • schema ml contains two materialized views that are used as features and read from the data loader

Application overview

main.py is the entry point, accepts commands:
  • train or predict
    • --regressor
    • --survival
  • embed or query
  • --learning-rate, --epochs, etc.

Outputs:

  • PyTorch models saved into
    models/<model-type>/yyyy_mm_dd/stupyd_model.py
  • Predictions saved into
    models/<model-type>/yyyy_mm_dd/stupyd.csv

Configuration (stupyd.json) shared at run-time.

Neural Network

Models

  • regressor: drop students not graduated. It is foolishly sure of the delay.
  • survival: consider six-months periods and evaluates probability of graduation and duration.

Loss: regressor


loss = functional.smooth_l1_loss( .. )

Use Huber Loss which acts as Mean Squared Error near the optimum (|error| < β) and Mean Average Error (linear) for the outliers.

Loss: survival


# loss function
loss = -( outcomes * torch.log( safe_hazard )
          + ( 1.0 - outcomes ) * torch.log( 1.0 - safe_hazard ) )

at_risk        = tensors[ "at_risk" ]
per_enrollment = ( loss * at_risk ).sum( dim = -1 )
return per_enrollment.mean()

Negative Log Likelihood: divide time in intervals (6 months) and the loss is the negative log of the probability the model assigns to the sequence observed.

Conclusions and future works

production un-ready!

  • playground to start working with neural networks, class hierarchy "pluggable"
  • a lot of parameters to be better understood (learning rate, epochs, hidden layers in MLP)
  • more loss functions to try
  • testing and validation period could be unbalanced (training 1900-2021, testing 2023, validating 2022)
  • embedding out of scope in here (but hey, it's PostgreSQL!)
